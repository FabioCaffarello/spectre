# Refactor audit — UDS removal targets

> Generated by R2.1 (companion to
> [ADR-0022 §5](adr/0022-tcp-grpc-transport.md)). This document
> lists every location in the repo at R2.1's merge point
> requiring change in R2.2 (adapter transport switch) or R2.3
> (engine transport + service mode). Each entry names the file,
> the relevant lines, the change required, and the target PR.
>
> The list is grep-derived. If a UDS reference is found during
> R2.2 / R2.3 implementation that is not in this list, the
> audit was incomplete — open an amendment PR adding it before
> proceeding.

## Conventions

- **R2.2** items are adapter-side: each adapter binary, each
  `driver.yaml`, the conformance harness, the per-adapter
  build recipes, and the per-adapter / example READMEs.
- **R2.3** items are engine-side: the launcher, the gRPC
  client, the engine binary entry point, the engine tests,
  and the engine packaging metadata.
- **Out-of-scope** items belong to later phases (R3.1 for
  control-plane runner, R3 for ADR-0012 revision, R6 for
  per-service Dockerfiles). They are listed at the end so
  reviewers can confirm the audit considered them.

## R2.2 — adapter transport switch

> from each `driver.yaml`; the three adapters bind TCP via
> `SPECTRE_ADAPTER_GRPC_PORT` and register the gRPC standard health

> `resolve_socket_path` against `adapters/` and `tools/conformance/`

## R2.3 — engine transport + service mode

> **Status (R2.3 complete):** every engine-side and cross-cutting
> entry below was applied in PR R2.3. `core/engine/src/launcher.rs`
> is gone; `Client::dial` accepts `host:port` / `grpc://host:port`
> endpoints and connects via `tonic::transport::Endpoint`'s TCP
> path; the engine binary is the gRPC service entry point on
> `0.0.0.0:9090`; adapter discovery flows through `AdapterRegistry`
> reading `SPECTRE_PLAYWRIGHT_ENDPOINT` /
> `SPECTRE_SELENIUMBASE_ENDPOINT` / `SPECTRE_CURL_IMPERSONATE_ENDPOINT`
> with `127.0.0.1:909{1,2,3}` defaults. A grep for `launcher`,
> `--socket`, `SPECTRE_DRIVER_SOCKET`, `UnixStream`, `:authority`,
> or `spectre run` against `core/engine/` returns zero hits. The
> R2.3 → R3.1 window leaves the operator's `SubprocessRunner`
> broken at runtime — that gap is closed by R3.1's
> `EngineClientRunner`, intentionally scoped as the next PR.

### core/engine/

| File | Lines | Change |
|------|-------|--------|
| `src/launcher.rs` | whole file | Retire entirely. The module's responsibilities (manifest reading for `grpc-uds`, UDS path allocation, subprocess spawn with `--socket=` and `SPECTRE_DRIVER_SOCKET`, readiness-line parsing, SIGTERM-driven socket unlink) disappear with the subprocess-in-pod model. `lib.rs` removes `pub mod launcher`. Tests in `mod tests` (lines 494–612) go with it. |
| `src/client.rs` | whole file (UDS-specific) | Rewrite the `Client::dial(socket: &Path)` signature into a TCP-dial signature taking `&str` endpoint URLs (`grpc://host:port`). Delete the `UnixStream::connect` connector, the `grpc.default_authority=localhost` `:authority` workaround, and the path-only validation. Add a `tonic-health` startup probe per ADR-0021 §6. |
| `src/engine.rs` | 117 | `Client::dial(handle.socket_path())` becomes `Client::dial(<endpoint>)`, where `<endpoint>` resolves from `SPECTRE_<ADAPTER>_ENDPOINT`. The `handle` source changes from `launcher::launch(…)` to a discovery helper. |
| `src/bin/spectre.rs` | whole file | Retire the `spectre run` CLI binary. ADR-0020 §3 retires the CLI entry point; the engine binary that survives is the gRPC service binary introduced in R2.3. |
| `Cargo.toml` | 28–36 (UDS / Tokio commentary), 66–73 (regex / nix rationale), `[[bin]]` section for `spectre` | Remove the `spectre` binary registration. Update dependency-rationale comments. Drop `nix` and `regex` if no remaining call site uses them after the launcher retires. |
| `Dockerfile` | 12 | Rewrite the comment that documents the engine spawning adapters; the engine becomes a service-mode-only binary. |
| `README.md` | 5, 146, 154–156 | Update module overview and file map: TCP transport, no launcher module. |
| `tests/integration.rs` | 14, 49 (`LocalServer::spawn()`), 59–67 | Rewrite to dial a TCP-bound stub server instead of spawning a subprocess and dialling its UDS. |
